# Semantic_BI

`Semantic_BI` — проект и система целиком. В проекте используются следующие названия компонентов:

- **S3→Fuseki-синхронизатор** — сервис, который читает события и манифесты Bitrix24 из S3, преобразует данные в RDF и обновляет именованные графы в Fuseki. Исходный код сервиса подключён в `cccr_pipeline` из отдельного репозитория. В документации компонент называется «синхронизатор»; `cccr_pipeline` — техническое имя репозитория.
- **Движок CCCR** (`cccr_engine`) — библиотека, которую синхронизатор использует для преобразования данных в RDF; она подключена как вложенный submodule репозитория `cccr_pipeline`.

Иными словами: синхронизатор использует движок CCCR. Эти термины применяются в документации проекта независимо от текущей структуры каталогов или будущих переименований репозиториев.

Для получения проекта со всеми внешними исходниками используйте рекурсивный clone:

```bash
git clone --recurse-submodules <URL-Semantic_BI>
```

Если репозиторий уже клонирован, выполните `git submodule update --init --recursive`.
Для доступа к вложенным репозиториям SourceCraft нужны права чтения по SSH. В CI настройте GitHub Actions secret `SOURCECRAFT_SSH_KEY` (read-only ключ) и repository variable `SOURCECRAFT_KNOWN_HOSTS` с заранее проверенной записью host key `ssh.sourcecraft.dev`.

Описание контракта S3 и Fuseki см. в [RDF_INTEGRATION.md](RDF_INTEGRATION.md).

Подробная логика первичной загрузки, обновления снимка, регулярной синхронизации,
checkpoint и обработки ошибок описана в [документе о логике загрузки S3 → Fuseki](docs/S3_TO_FUSEKI_LOADING.md).

Известные ограничения run ID и восстановления очереди, отложенные на следующий этап,
собраны в [SYNC_RELIABILITY_BACKLOG.md](docs/SYNC_RELIABILITY_BACKLOG.md).
